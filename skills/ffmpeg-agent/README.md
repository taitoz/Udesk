# FFmpeg Agent — реставрация VR180 и генерация задач для Quest 2

Локальный AI-агент анализирует метаданные и изображения VR-видео с помощью **Gemini 2.5 Flash**, проверяет профиль реставрации на коротком образце и формирует JSON-задачи для последующего сохранения в очередь XBVR.

**Финальное кодирование не запускается.** `executeBatch()` только возвращает структуры задач: не вызывает FFmpeg, не создаёт выходную директорию и не записывает данные в БД. FFmpeg запускается на этапе анализа для захвата кадров и тестового кодирования до 5 секунд.

## Стек и файлы

- Node.js, стандартные модули `child_process`, `fs`, `os`, `path`.
- `@google/genai`, модель по умолчанию — `gemini-2.5-flash`.
- FFmpeg / ffprobe в `PATH`, NVIDIA GPU с рабочим драйвером CUDA/NVENC.

```text

```

## Конвейер

### 1. scanFolder(inputPath)

Принимает директорию или отдельный видеофайл. Директория сканируется плоско, без рекурсии; при передаче файла соседние видео не обрабатываются. По умолчанию выбираются только `.mp4`; список расширений можно изменить через `videoExts`.

Для каждого файла собираются метаданные `ffprobe`. Если файл не удалось прочитать или разобрать ответ ffprobe, сканирование продолжается, а файл исключается с предупреждением.

### 2. analyzeAndEstimate(files, onProgress)

Для каждого файла:

1. Выбирается случайная точка в центральной части видео, обычно между 35% и 65% длительности и после первой минуты. Для коротких видео позиция ограничивается доступной длительностью. `testOffsetMin` позволяет задать фиксированное смещение в минутах.
2. Сохраняется исходный кадр в Lossless WebP через `-ss ... -vframes 1 -c:v libwebp -lossless 1`.
3. В Gemini передаются метаданные и исходное изображение как `inlineData` с MIME-типом и base64. `QUEST2_OPTIMIZATION_PROMPT` запрашивает необходимость кодирования, подтверждение визуальной чистоты и решения по цвету/контрасту. Конкретные аргументы FFmpeg формирует приложение, а не модель.
4. Для кандидата на кодирование запускается тестовый образец до 5 секунд с профилем реставрации.
5. Результат повторно проверяется через ffprobe: HEVC, размеры не больше 6144×3072 и FPS не выше 60.
6. Захватывается первый кадр результата. В Gemini отправляются подписанные изображения **BEFORE / AFTER**, метаданные и BPP. `VR_QUALITY_ASSESSMENT_PROMPT` оценивает остаточную сетку AVC, шум, желтизну, яркость/контраст, резкость и ореолы.
7. Возвращается внутренняя очередь с параметрами, оценкой и ориентировочным временем полного кодирования. Оценка времени экстраполируется из времени тестового кодирования, без времени запроса Gemini, с коэффициентом 0.8; это не гарантия скорости.

Изображения и образец размещаются в уникальной временной директории и удаляются после обработки файла. Критическая ошибка анализа одного файла не останавливает остальные файлы пакета.

### 3. executeBatch(queue, outputPath, onProgress)

Несмотря на историческое название, метод **только генерирует команды**:

- `PASS` и `WARN` включаются в результат.
- Исключаются только явные `action: "skip"` и `assessment.status: "FAIL"`.
- Отсутствующая или неизвестная оценка нормализуется в `WARN`, а не теряет задачу.
- Каждая задача содержит `file_name`, `input_args` и **две независимые команды**: `pure_cuda` и `full_restored` — каждая со своими `output_args`, `output_file` и `full_command`.
- `pure_cuda` — чистый GPU-вариант: только `scale_cuda` + NVENC, без CPU-фильтров. Результат — `<имя>_pure_cuda.mp4`.
- `full_restored` — полная реставрация: CPU-фильтры по флагам модели + `unsharp`, затем загрузка на GPU и `scale_cuda`. Результат — `<имя>_restored.mp4`.
- Без `outputPath` используется директория исходника.
- Callback получает событие `task-generated`.

## Критерии пропуска и статусы

Пропуск разрешён **только для исходника**, который одновременно:

1. Подтверждён моделью как визуально чистый (`source_clean: true`): нет сетки AVC, шума или желтизны и нет необходимости в улучшении.
2. Совместим с политикой Quest 2: HEVC/H.264, размеры ≤6144×3072, известный FPS ≤60.
3. Не требует обязательного преобразования профиля, например апскейла низкого разрешения или перевода H.264 шириной больше 4096 в HEVC.

Неизвестный FPS, отсутствие исходного изображения или неподтверждённая чистота не позволяют принять `skip`. Успешная реставрация тестового кадра не означает, что можно пропустить исходник.

| Статус | Значение | Команда в итоговой очереди |
| --- | --- | --- |
| `PASS` | Приемлемое качество и совместимость | Да |
| `WARN` | Некритичные замечания, остаточные артефакты или неопределённость | Да, с сохранением заметки |
| `FAIL` | Критическая ошибка кодирования/анализа, нечитаемый поток или непригодный технический результат теста | Нет |
| `SKIP` | Исходник не требует преобразования; внутренний статус при `action: "skip"` | Нет |

Сбой Gemini или визуального сравнения **после успешной технической проверки образца** даёт `WARN`. Ошибка тестового кодирования или технической проверки — `FAIL`.

BPP рассчитывается как `bitrate / (width × height × fps)` и служит контекстом для оценки. **Низкий BPP не является основанием для пропуска.** Рост битрейта или размера допускается при обоснованной реставрации и апскейле и сам по себе не считается регрессией.

## Профили разрешений и фильтры

- Низкое разрешение: высота ≤1920 — фиксированный апскейл до **4800×2400**.
- Oversized (ширина >6144 или высота >3072) — фиксированный даунскейл до **6144×3072**, строго без CPU-фильтров (чистый GPU, максимальная скорость).
- Все остальные исходники до 3072p кодируются в родном разрешении; фильтры в `full_restored` подбираются по флагам модели (`remove_grid`, `color_correct`, `adjust_contrast`), `unsharp` применяется всегда, `eq` — дополнительно для видео ≤2400p.
- Исходный FPS сохраняется, включая дробную запись `60000/1001`; значения выше 60 ограничиваются до 60. При неизвестном FPS профиль использует 30.

Последовательность фильтров:

```text
# pure_cuda (всегда только GPU):
[yadif_cuda=mode=1,]               # при interlaced
scale_cuda=W:H:format=nv12:interp_algo=bicubic

# full_restored (CPU-реставрация → GPU):
hwdownload,format=nv12,format=yuv420p,
yadif=mode=1,                                        # при interlaced
v360=input=fisheye:output=equirectangular:...,       # при fisheye/correct_geometry
stereo3d=sbsl:sbsr,                                  # при swap_lr
spp=4:0:1,hqdn3d=1:1:1:1,          # при remove_grid
hqdn3d=3:2:6:4.5,                  # при remove_noise без remove_grid
colortemperature=temperature=7500, # при color_correct
eq=contrast=1.03:brightness=0.01,  # при adjust_contrast или ≤2400p
unsharp=5:5:1.6:5:5:0,format=yuv420p,hwupload_cuda,
scale_cuda=W:H:format=nv12:interp_algo=bicubic
```

Фильтры подключаются по флагам модели в `restoration`: `remove_grid`, `remove_noise` (независимо — шум без сетки), `color_correct`, `adjust_contrast`, `correct_geometry`/`projection_type: "fisheye"`, `interlaced`, `swap_lr`. Геометрия и деинтерлейс идут первыми в цепочке — до денойза и шарпенинга. `unsharp=5:5:1.6:5:5:0` в полном профиле применяется всегда; для видео ≤2400p `eq` включается автоматически. Oversized-источники (>3072p) не используют CPU-путь ни в одном варианте. Флаги `fisheye`, `correct_geometry`, `swap_lr`, `interlaced` делают кодирование обязательным (`mandatory`).

Для 10-битного исходника перед CPU-фильтрами используется `format=p010le` вместо `nv12`. Температура 7500K применяется только при видимой желтизне.

`hwdownload` необходим, поскольку `spp`, `hqdn3d` и цветокоррекция выполняются на CPU. Повторный **`format=yuv420p` перед `hwupload_cuda`** предотвращает ошибку `rgb0 -> semiplanar8` после цветовых фильтров. Масштабирование и кодирование выполняются на GPU.

Параметры кодирования: `hevc_nvenc`, `p4`, `hq`, VBR, CFR, тег `hvc1`, копирование аудио и `+faststart`.

| Ширина результата | `-b:v` | `-maxrate` | `-bufsize` |
| --- | --- | --- | --- |
| ≤4800 | 30M | 45M | 60M |
| >4800 | 40M | 60M | 100M |

## Установка и CLI

В директории агента установите зависимости из существующего `package.json`:

```bash
npm install
ffmpeg -version
ffprobe -version
```

FFmpeg должен включать фильтры `spp`, `hqdn3d`, `colortemperature`, `unsharp`, `eq`, `v360`, `yadif`, `yadif_cuda`, `stereo3d`, `hwdownload`, `hwupload_cuda`, `scale_cuda`, кодировщик `libwebp` и энкодер `hevc_nvenc`. Одного наличия CUDA-флагов в сборке недостаточно: необходим доступный NVIDIA-драйвер. Ошибка загрузки `nvcuda.dll` означает, что аппаратный прогон недоступен в текущем окружении.

Установите `GEMINI_API_KEY` в окружении. Ключ не передаётся аргументом командной строки и не должен сохраняться в репозитории.

PowerShell (после настройки переменной окружения):

```powershell
node .\test-run.js "D:\Videos" "D:\Output" > tasks.json
```

Bash (после настройки переменной окружения):

```bash
node test-run.js ./videos ./out > tasks.json
```

Первый аргумент — директория или отдельный `.mp4`-файл. Например, `node test-run.js "./videos/clip.mp4" ./out` обрабатывает только выбранный файл. Второй аргумент, директория отчётов и будущих результатов, необязателен; по умолчанию используется директория источника. Подтверждений и интерактивного retry нет.

- **stdout**: один JSON-объект, если сгенерирована одна задача; массив, если задач несколько; `[]`, если задач нет, включая пустую входную папку.
- **stderr**: прогресс, диагностика, количество исключённых файлов и путь сохранённого отчёта.
- CLI дополнительно сохраняет текстовый файл с готовыми командами ffmpeg (по две на задачу: `pure_cuda` и `full_restored`, с `rem`-заголовками для вставки в консоль): `<имя-видео>_commands.txt` для отдельного файла или `optimization_commands.txt` для директории. Если имя занято, используются суффиксы `_1`, `_2` и далее; существующие файлы не перезаписываются.
- Входной путь и тип выходного пути проверяются до создания агента и проверки API-ключа. Выходная директория создаётся только после успешного анализа, непосредственно перед сохранением отчёта.
- Выходные видео не создаются. Дополнительный `tasks.json` в примерах создаётся перенаправлением stdout оболочки; не направляйте вывод в существующий файл, который хотите сохранить.

## Формат итоговой задачи

Пример для реставрации 3840×1920 с подтверждённой желтизной (команды показаны для Bash; `full_command` сокращён):

```json
{
  "file_name": "example.mp4",
  "action": "encode",
  "target_resolution": "4800:2400",
  "input_args": ["-hwaccel", "cuda", "-hwaccel_output_format", "cuda"],
  "pure_cuda": {
    "output_file": "/out/example_pure_cuda.mp4",
    "output_args": [
      "-vf", "scale_cuda=4800:2400:format=nv12:interp_algo=bicubic",
      "-fps_mode", "cfr", "-r", "60000/1001",
      "-c:v", "hevc_nvenc", "-preset", "p4", "-tune", "hq", "-rc", "vbr",
      "-b:v", "30M", "-maxrate", "45M", "-bufsize", "60M",
      "-tag:v", "hvc1", "-c:a", "copy", "-movflags", "+faststart"
    ],
    "full_command": "ffmpeg '-hwaccel' 'cuda' ... '/out/example_pure_cuda.mp4'"
  },
  "full_restored": {
    "output_file": "/out/example_restored.mp4",
    "output_args": [
      "-vf", "hwdownload,format=nv12,format=yuv420p,colortemperature=temperature=7500,eq=contrast=1.03:brightness=0.01,unsharp=5:5:1.6:5:5:0,format=yuv420p,hwupload_cuda,scale_cuda=4800:2400:format=nv12:interp_algo=bicubic",
      "-fps_mode", "cfr", "-r", "60000/1001",
      "-c:v", "hevc_nvenc", "-preset", "p4", "-tune", "hq", "-rc", "vbr",
      "-b:v", "30M", "-maxrate", "45M", "-bufsize", "60M",
      "-tag:v", "hvc1", "-c:a", "copy", "-movflags", "+faststart"
    ],
    "full_command": "ffmpeg '-hwaccel' 'cuda' ... '/out/example_restored.mp4'"
  },
  "rationale": "Устранение желтизны и апскейл до 2400p.",
  "assessment": {
    "status": "WARN",
    "grid_removed": false,
    "color_corrected": true,
    "notes": "Цвет нормализован; остаточная сетка требует проверки, команда сохранена в очереди."
  }
}
```

`input_args` не содержит `-i` или имя файла; они добавляются при формировании `full_command`. Экранирование полной команды зависит от платформы агента. Для программного запуска будущим обработчиком очереди предпочтительнее передавать массивы аргументов в `spawn`, а не исполнять строку через shell.

## API и внутренняя очередь

Папка агента имеет собственный CommonJS `package.json`; при переносе копируйте его вместе с кодом.

```js
const { FfmpegAgent } = require('./index');

async function generateTasks() {
    const agent = new FfmpegAgent({
        apiKey: process.env.GEMINI_API_KEY,
        model: 'gemini-2.5-flash',
        videoExts: ['.mp4'],
        testOffsetMin: null,
    });
    const files = await agent.scanFolder('./videos');
    const queue = await agent.analyzeAndEstimate(files);
    return agent.executeBatch(queue, './out');
}
```

`testOffsetMin: null` — случайное смещение по длительности; например, `testOffsetMin: 5` задаёт пятую минуту с ограничением по длине файла. Через `promptTemplate` можно переопределить промпт начального анализа, но детерминированные профили и обязательные ограничения приложения сохраняются.

`analyzeAndEstimate()` возвращает внутренние элементы с `name`, `path`, `ext`, `metadata`, `action`, `inputArgs`, `outputArgs`, `rationale`, `testSuccess`, `testDurationMs`, `outputProbe`, `assessment`, `estimatedSeconds` и `duration`. При критической ошибке отдельного файла набор полей может быть сокращён; элемент получает `FAIL` и исключается в `executeBatch()`.

Публичные задачи используют snake_case (`file_name`, `input_args`, `pure_cuda`, `full_restored`) и не включают все внутренние метаданные. Внутренние элементы очереди дополнительно хранят `pureCudaArgs` и `fullRestoredArgs` в camelCase. Метод `executeBatch()` всегда возвращает **массив**, независимо от количества задач; преобразование одиночной задачи в объект выполняет только CLI.

## Проверки

В директории агента:

```bash
npm test
node --check index.js
node --check test-run.js
```

Тесты используют встроенный `node:test` и моки Gemini/FFmpeg: проверяют включение PASS/WARN, исключение skip/FAIL, критерии пропуска, восстановление после сбоя Gemini, продолжение батча после ошибки файла, формат задач, временные файлы и порядок CPU/CUDA-фильтров для 8/10-битных исходников. Они не подтверждают фактическую работу драйвера NVIDIA или качество реального видео.

## Ограничения и дальнейшая интеграция

- Один короткий образец не гарантирует одинаковое качество во всём видео; визуальные выводы модели требуют проверки, особенно при `WARN`.
- Текущие целевые профили ориентированы на Quest 2, даже если контент будет воспроизводиться на Quest 3.
- Сохраняются пропорции кадра; автоматического преобразования стереораскладки или VR-проекции нет.
- Аудио копируется без перекодирования; несовместимость исходного аудио с MP4 может привести к ошибке теста.
- Выбор GPU, рекурсивное сканирование и автоматический повтор с изменением фильтров не реализованы.
- Подключение к БД XBVR, сохранение задач, дедупликация и запуск финального кодирования — ответственность будущего обработчика очереди. Агент этих действий не выполняет.
